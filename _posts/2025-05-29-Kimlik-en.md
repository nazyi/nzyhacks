**Account Types**

Personal: A real user account

Privileged: An account that can manipulate information on a system

Generic: Used by multiple real people for a common purpose

Service: An account used for a specific operation on a system

**Account Statuses**

Locked: An account that has made as many wrong attempts as specified in the policy

Idle: An account that has not been logged into for the period specified in the policy

Orphan: An account with no owner

Rogue: An account created outside of the system's knowledge

**RACI**

Responsible: Who is responsible for the work?

Accountable: Who manages the work?

Consulted: Who do we ask about how the work should be done?

Informed: Who do we give information to?

**SAML**

SAML is an XML-based authentication and authorization protocol. It allows a user to securely share their authentication information across multiple applications.

*   **Identity Federation**: Users can access different services without logging in again after logging in once (Single Sign-On — SSO).
*   **XML-Based**: Identity information and access permissions are transmitted in XML format.
*   **IdP (Identity Provider)**: Verifies the user's identity (for example, Google, Microsoft AD FS).
*   **SP (Service Provider)**: The application or service that accepts that the user has been verified (for example, Salesforce, Dropbox).
*   **Enterprise Use**: Generally used in enterprise-level applications and large companies.

**oAuth** 

An authorization protocol that allows third-party applications to access a resource without knowing the user's password. Its most widely used version is **OAuth 2.0**.

*   **It's for Authorization**: OAuth focuses more on determining an application's authorization to access specific resources than on user authentication.
*   **It Uses Tokens**: It works with JSON Web Tokens (JWT) or Bearer Tokens.
*   **Identity Providers**: Services like Google, Facebook, and GitHub offer OAuth-based authorization.
*   **Mobile and Web API Friendly**: Its lightweight, JSON-based structure makes it suitable for modern applications.

**Terms**

OTP: One-time password  
SSO: Signing into multiple applications with a single authentication  
MFA: Multi-factor authentication  
2FA: Two-factor authentication
