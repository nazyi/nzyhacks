In this post I'll try to explain what RADIUS, EAP, PEAP, and more actually are.

## Two Kinds of Wi-Fi

We can roughly split Wi-Fi security standards into two.

The first is **WPA2-Personal** or **WPA3-Personal**, the standard used at home, where you connect with the password printed on the back of the modem or a shared password everyone knows.

But using the same setup in a company would be a tough scenario. Employees could keep connecting to the network even after leaving the company because they still know the password, and if the password got shared, people outside the company could get on the network too.

That's exactly why companies use **WPA2-Enterprise** or **WPA3-Enterprise**. With these standards, instead of a shared password, each employee signs in with their own credentials, which makes for a more secure network.

In both kinds, WPA also encrypts the traffic on the network.

### EAP: Authentication Rules

How authentication is done between the device and the RADIUS server depends on a few different sets of rules. The general name for these rules is **EAP**, and there are different types.

- **PEAP:** An encrypted tunnel is set up between the device and the server using the server's certificate. The username and password are sent through this tunnel, so no one outside can see them. PEAPv0, mentioned in the warning, is the most common version of PEAP and uses MSCHAPv2 inside the tunnel. It's easy to set up because Windows and macOS support it out of the box.
- **EAP-TTLS:** Similar to PEAP in concept. Again, an encrypted tunnel is set up with the server certificate and the credentials are sent through it. The difference is that it also allows other authentication methods, such as PAP, inside the tunnel.
- **EAP-TLS:** The most secure method. No passwords are used at all; instead, each user or device has its own digital certificate, and identity is proven with it. It's the hardest to set up, because a separate certificate has to be distributed to every device.

With PEAP and EAP-TTLS, the device needs to trust the server certificate to be sure the server it's connecting to really is the company's. These are the most commonly used EAP types.

## Back to the Warning

JumpCloud is changing its RADIUS server certificate on October 25th. Since both PEAP and EAP-TTLS set up their tunnel with this certificate, the warning covers both.

Whether anyone needs to do something depends less on the protocol and more on how the certificate was introduced to the device:

- If the Wi-Fi settings were pushed to devices with an MDM profile and the old server certificate is defined in the profile, the profile has to be updated with the new certificate. Otherwise devices won't be able to connect.
- If the user trusted the certificate themselves the first time they connected, they'll usually get the same prompt once more when connecting after the change.
